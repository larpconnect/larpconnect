## Why

**Njall** currently exposes a placeholder `POST /api/studios/{studio-id}/v1/actors/{actor-id}/inbox`
endpoint that accepts arbitrary JSON, discards the payload, and returns `201 Created`, leaving the
platform unable to validate, deduplicate, route, or asynchronously queue inbound **FeatherPub**
**Activity** messages. Implementing the **FeatherPub** inbox ingress boundary (`docs/FEATHERPUB.md`)
on top of AMQP 1.0 (RabbitMQ 4.3+) and PostgreSQL-backed deduplication establishes the asynchronous
API-to-queue contract needed before building downstream **Activity** state consumers and
server-to-server `at+jwt` federation signatures.

## What Changes

- **BREAKING**: Replace the no-op `201 Created` `POST .../actors/{actor-id}/inbox` stub in `:api`
  with validated **FeatherPub** **Activity** ingress returning `202 Accepted` across three endpoints
  under `/api/studios/{studio-id}/v1/actors/{actor-id}`:
  - `POST .../inbox` and `POST .../inbox:message` for single **Activity** delivery (`202 Accepted`).
  - `POST .../inbox:batchMessage` adhering to Google AIP-233 (`{ "requests": [ ... ] }`, not wrapped
    in a **FeatherPub** `@context` object) with partial-success execution and index-keyed
    `failedRequests` reporting (`202 Accepted` when at least one item is accepted; `400 Bad Request`
    when zero items succeed or `requests` is empty).
- Support resolving `{actor-id}` by canonical UUID or case-insensitive `preferredUsername` on
  `GET .../actors/{actor-id}`, `GET .../actors/{actor-id}/inbox`, and all inbox delivery endpoints,
  while deferring studio-level `default` **Actor** provisioning to a later change.
- Validate the union-free discriminated 10-verb **FeatherPub** **Activity** wire contract (`Create`,
  `Update`, `Delete`, `Add`, `Remove`, `Move`, `Offer`, `Accept`, `Reject`, `Announce`), optional
  `Content-Digest` (`sha-256` and `sha3-256`) integrity verification, same-origin/subdomain
  authority between absolute `id` and `actor` URIs, and temporal bounds (`created` within clock skew
  and the 8-day retry window; `updated >= created` on embedded objects).
- Perform pre-queue **generator**-hierarchy recipient routing at HTTP ingress: extract local
  **Studio** candidate **Actor** recipients from `to` and `cc` (resolving UUIDs and
  `preferredUsername`s) and verify via recursive ancestor traversal of
  `njall_users.entities.generator` that each candidate is either the receiving `{actor-id}` or
  transitively generated by it.
- Add Flyway migration `V15__inbox_activity_deduplication.sql` in `:data` creating
  `njall_users.inbox_activities` with PostgreSQL Row-Level Security (`app.tenant_id`) and front it
  with an in-memory Caffeine cache to enforce durable 8-day `(tenant_id, target_actor_id,
  activity_id)` idempotency across **Server** restarts, recording deduplication keys only after
  broker acceptance.
- Introduce a new `:queue` Gradle **Library module** (`com.larpconnect.njall.queue`) backed by
  RabbitMQ's official AMQP 1.0 Java client (`com.rabbitmq.client:amqp-client` `1.7.0`, replacing
  legacy AMQP 0-9-1 `com.rabbitmq:amqp-client` in the version catalog), publishing one durable
  AMQP 1.0 JSON message per accepted **Activity** with W3C `traceparent` propagation, coordinated
  **Server** startup/shutdown lifecycle, and a Caffeine-cached `AmqpHealthCheck`.
- Stand up `rabbitmq` (`rabbitmq:4.3-alpine` with native AMQP 1.0 on the `internal` Docker network
  and `NJALL_DB_SECRET`-derived credentials) in `docker-compose.yml`.

## Capabilities

### New Capabilities
- `amqp-queue-messaging`: Dedicated `:queue` **Library module** (`com.larpconnect.njall.queue`)
  providing AMQP 1.0 connection and publisher lifecycle management against RabbitMQ 4.3+, durable
  JSON envelope publication with broker disposition confirmation and W3C `traceparent` propagation,
  and a 10-second Caffeine-cached Dropwizard `HealthCheck`.
- `featherpub-inbox-api`: Tenanted **User plane** HTTP endpoints (`POST .../inbox`,
  `POST .../inbox:message`, and AIP-233 partial-success `POST .../inbox:batchMessage`) performing
  `Content-Digest` verification, union-free 10-verb **FeatherPub** **Activity** validation,
  pre-queue **generator**-hierarchy recipient routing, Caffeine + PostgreSQL 8-day deduplication,
  and AMQP 1.0 queue publication returning `202 Accepted`.

### Modified Capabilities
- `user-studio-actors-api`: **BREAKING** change splitting `POST .../inbox` (now `202 Accepted`
  **FeatherPub** **Activity** ingress) from `POST .../outbox` (`201 Created`), and resolving
  `{actor-id}` by UUID or case-insensitive `preferredUsername` on **Actor** retrieval and inbox
  endpoints.
- `database-migration`: Add Flyway migration `V15__inbox_activity_deduplication.sql` creating
  `njall_users.inbox_activities` with composite foreign keys to `njall_users.actors`, expiration
  indexing, Row-Level Security policies, and role grants.
- `data-persistence`: Add case-insensitive `preferredUsername` **Agent** lookup, recursive
  `njall_users.entities.generator` ancestor routing queries, and tenanted `InboxActivityDAO`
  persistence in `com.larpconnect.njall.data.dao.studios.inbox` with immutable domain models in
  `com.larpconnect.njall.data.domain.inbox`.
- `system-runtime-orchestration`: Add `rabbitmq` (`rabbitmq:4.3-alpine`, AMQP 1.0 on port `5672` on
  `internal` network with `NJALL_DB_SECRET` credential derivation and healthcheck barrier) to
  `docker-compose.yml` before `server` startup.
- `admin-healthcheck`: Include the Caffeine-cached AMQP 1.0 broker connectivity check in
  `/api/admin/v1/health` evaluation so broker outages report `500 Internal Server Error`.
- `http-server-runtime`: Coordinate `AmqpQueueService` startup prior to HTTP socket binding and
  graceful stop during `CoordinatedShutdown` within `DefaultServerManagerService`.
- `architectural-invariants`: Extend module, `api.studios`, `data.dao.studios`, and `data.domain`
  package topology rules for `:queue`, `api.studios.inbox`, `data.dao.studios.inbox`, and
  `data.domain.inbox`.

## Impact

- **Glossary**: Adds **Activity** to `glossary/business.md`.
- **Build & Dependencies (`settings.gradle.kts`, `gradle/libs.versions.toml`, `parent`, `bom`)**:
  Replaces `com.rabbitmq:amqp-client` (AMQP 0-9-1) with `com.rabbitmq.client:amqp-client:1.7.0`
  (AMQP 1.0) and registers the new `:queue` **Library module**.
- **Queue Module (`:queue`)**: New **Module** under `com.larpconnect.njall.queue` (`config`,
  `publisher`, `health`) with `QueueModule` installed by `ServerModule` in `:server`.
- **Database & Data Module (`:data`)**: Adds `V15__inbox_activity_deduplication.sql`, extends
  `AgentDAO` for `preferredUsername` resolution, and adds `data.domain.inbox` and
  `data.dao.studios.inbox` (`InboxActivityDAO`) for recursive **generator** routing and 8-day
  deduplication.
- **API & Server Modules (`:api`, `:server`, `:common`)**: Updates `openapi.yaml` and
  `reference.conf`; adds `com.larpconnect.njall.api.studios.inbox` (`InboxRoute`, `InboxActor`,
  validation, **DTO** envelopes, and Caffeine L1 deduplication cache); delegates inbox routes from
  `AgentRoute`; wires `AmqpQueueService` into `DefaultServerManagerService`.
- **Infrastructure & Integration (`docker-compose.yml`, `:integration`)**: Adds `rabbitmq:4.3-alpine`
  to Docker Compose and adds Cucumber API-to-Queue boundary features (using Testcontainers
  PostgreSQL and RabbitMQ 4.3+) plus updated `ArchitectureTest` coverage.
